# Kế hoạch triển khai ItemGuard MVP an toàn

**Mục tiêu:** Xây ItemGuard cho Paper 1.21.11 với identity vật phẩm duy nhất, duplicate evidence fail-closed, lịch sử/search, reclaim không tạo bản sao và tích hợp plugin qua adapter có capability rõ ràng.

**Kiến trúc:** Tách Bukkit adapter khỏi domain. Bukkit thread tạo immutable item observations; domain detector phân loại duplicate; SQLite repository sở hữu một executor/connection tuần tự; command/GUI gọi async và chỉ quay lại main thread để chạm Bukkit. Destructive behavior bị khóa sau release gate.

**Tech stack:** Java 21, Paper/Spigot API 1.21.11, Maven Wrapper 3.9.16, JUnit Jupiter 5.11.4, Xerial SQLite JDBC 3.53.2.1, Maven Shade 3.6.2.

**Source of truth:** `AGENTS.md` khi được user duyệt, `CURRENT_STATE.md`, `docs/RISK_REGISTER.md`, `docs/PRODUCT_REQUIREMENTS.md`, source/tests/Git.

**Modify:**

**RED:** item trong storage slot/off-hand/armor được tag đúng slot; main hand không bị ghi đè; scan dừng ở budget và tiếp tục bằng cursor.

### Task 2.3: Main-thread revalidation

Trước quarantine/action, re-read exact holder/slot và so UUID/fingerprint; stale observation chỉ thành `SUSPECTED`, không xóa.

## Phase 3 — Persistence v2, SQLite-only MVP

### Task 3.1: Single-owner SQLite executor

**Create:**
- `persistence/SqliteStore.java`
- `persistence/StoreState.java`

**Modify:** call sites đang dùng `DatabaseManager` sync.

Mọi JDBC operation chạy trên một executor tuần tự. Public API trả `CompletableFuture<T>`. `close()` ngừng nhận task mới, drain bounded, commit, close; callback sau close bị reject/suppress.

**Tests:** concurrent writes serialized, close/drain, reject-after-close, no callback mutation after close.

### Task 3.2: Schema v2 + migration gate

Logical tables: metadata/schema_version, item_identity/full snapshot, observations, history, duplicate_case/evidence, search_job, reclaim_grant/claim, notification_ack, audit_log.

**Tests:** fresh DB, v1→v2 migration, restart, corrupt file, future schema rejection, no overwrite on unsupported data.

MVP công bố SQLite-only. MySQL/PostgreSQL config bị reject/restart-required cho tới khi có dialect/runtime suite.

### Task 3.3: Full-fidelity ItemStack snapshot

Serialize qua API Paper/Bukkit đúng version đã xác minh; version, checksum, size limit. Corrupt/future snapshot không được cấp lại hoặc silently reset.

## Phase 4 — Admin search/find workflow

### Task 4.1: Search jobs

Implement `/finditem startfinding|starttaking|stopfinding|listfinding|removefinding|clearfinding` với duration parser, persistence, pagination, acknowledgement và audit.

`starttaking` chỉ quarantine sau confirmed + revalidation; không delete.

### Task 4.2: Info/notification commands

Implement `readfinding`, `readdupe`, `checktps`, `infoplayer`, `infoitem`, `infodupe`.

Metrics: scan duration p50/p95/max, budget usage, backlog, DB queue—not chỉ server TPS.

### Task 4.3: Give commands

- `givefoundid`: chỉ consume quarantined artifact transaction.
- `givenewid`: clone full snapshot, sinh identity mới, audit admin reason.
- `giveoldid`: deny nếu canonical absence chưa được chứng minh.

## Phase 5 — Player reclaim

### Task 5.1: State machine/cooldown/quota

Implement `/matdo check`, `/matdo sos <id>` cùng states `ELIGIBLE→CHECKING→APPROVED→CLAIMED/DENIED`, idempotency key, cooldown, rolling quota và audit.

### Task 5.2: Presence adapters

Interface `ItemPresenceAdapter` với `READY/UNAVAILABLE/ERROR/TIMEOUT`. Built-in inventory/ender chest trước. PlayerVaults/zAuctionHouse chỉ sau research đúng plugin/version/public API. Bất kỳ required adapter không READY → deny reclaim.

### Task 5.3: Atomic claim

Concurrent claim requests chỉ một transaction thắng; inventory full dùng mailbox/quarantine delivery, không drop ra đất.

## Phase 6 — Transfer restrictions và trade

Cần decision UX trước khi bật. Thiết kế trade GUI hai bên: add protected item, lock, review, dual confirm, atomic swap/revalidation/cancel. Sau khi trade path controlled-runtime verified mới bật block drop/container.

Test matrix: normal drop, death, hopper, chest/shulker/ender chest, anvil/smithing/craft, plugin GUI, admin bypass, disconnect/restart trong trade.

## Phase 7 — Placeholder, GUI, integrations

- PlaceholderAPI namespace rõ ràng, không dùng `%id%` global mơ hồ nếu API không cho phép.
- Admin GUI: identity, snapshot, owner/history, duplicate evidence, search/reclaim/audit actions.
- Player GUI: reclaim eligibility/cooldown/quota/reason.
- WorldGuard/Vault chỉ giữ khi use case/API đúng version; dependency failure trong destructive/reclaim path phải fail-closed.

## Rủi ro/open decisions

- Stackable identity split/merge là release gate riêng; MVP ưu tiên non-stackable.
- Trade UX cần user duyệt trước Phase 6.
- Exact PlayerVaults/zAuctionHouse names/versions/API phải lấy từ server/plugin manifest hoặc user trước adapter implementation.
- Không coi build/unit xanh là runtime verified.
